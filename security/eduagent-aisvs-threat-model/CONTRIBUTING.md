# Contributing

Contributions should keep the project defensive, reproducible, and suitable for public review.

Acceptable contributions include:

- Threat-model improvements.
- Control mapping refinements.
- Evidence requirements.
- Synthetic lab scenarios.
- Validation checks.
- Documentation that improves safe adoption.

Do not submit:

- Real student data, credentials, logs, grades, or institutional records.
- Instructions for unauthorized testing.
- Operational exploit chains against real systems.
- Vendor accusations without verifiable public evidence.
- Content copied from proprietary standards, private reports, or restricted documents.

When adding scenarios, use synthetic identities, mocked services, and clearly bounded assumptions.
